# Resource Server — High-Level Specification

## Purpose
Resource Server is a lightweight, temporary file-sharing service. Users (people or automated
agents) drop a file in, receive a short identifier, and anyone on the network can open that
file through a simple link. It is intended for quickly sharing short-lived content such as
web pages, documents, data files, and text — not for long-term storage.

## Core Concepts
- **Resource** — a single stored file, together with its name, its type, its size, and
  when it was stored.
- **Resource ID** — a short, unique identifier assigned when a resource is stored. It is
  used to view or replace that resource.
- **Lifetime** — every resource is temporary and is removed automatically when it expires.

## Features

### 1. Upload a resource
- A user can upload one file at a time, either an existing file or content produced on the
  spot (for example, output generated by a script or agent).
- The user can optionally say what kind of content the file is (web page, structured data,
  plain text, or PDF) so it is shown correctly when opened.
- On success the user receives the resource ID, the file name, the content type, the size,
  the time it was stored, and a link to view it.
- Uploads with no file or an empty file name are rejected with a clear message.

### 2. View a resource
- Anyone with a resource's link can open it.
- The content is shown in its natural form: web pages render as pages, PDFs open as
  documents, text shows as text, and so on.
- The original file name is kept and offered to the viewer.
- Asking for a resource that doesn't exist, or has expired, gives a clear "not found" result.

### 3. Replace a resource
- Anyone can replace the content of an existing resource by uploading a new file under the
  same resource ID.
- The link stays the same, so anyone already holding it sees the new content.
- Replacing a resource restarts its lifetime.
- Trying to replace a resource that doesn't exist is rejected.

### 4. Browse all resources
- Anyone can see a list of all current resources, showing each one's ID, name, type, size,
  when it was stored, when it expires, and a link to open it.
- People opening the list in a browser get a readable, visual page. Automated tools get the
  same information in a structured, machine-readable form.
- Resources that will expire soon are highlighted.
- When there are no resources, the list says so and explains how to add one.
- Visiting the service's main address takes the visitor straight to this list.

### 5. Service status
- A status check reports whether the service is up and how many resources it currently holds.

### 6. Service management
- An operator can start, stop, and restart the service, check whether it is running, and
  follow its activity log.
- A full reset returns the service to a clean state. Like any restart, it discards all
  stored resources.
- The operator can run the automated test suite with a single command.

### 7. Agent skill guide
- The project includes a skill guide that teaches AI agents how to use the service on
  their own, without human help.
- The guide covers everything an agent needs:
  - starting the service and confirming it is running;
  - uploading a file or generated content, including how to say what kind of content it is;
  - building a shareable link that works for other people on the network, not only on
    the machine running the service;
  - replacing a resource and browsing all resources;
  - managing the service (stop, restart, status, logs) and troubleshooting common problems,
    such as the service not running or its address already being in use.
- The guide states the same rules as this document: the 10 MB file limit, the 24-hour
  lifetime, temporary storage, and open access where anyone can overwrite any resource.
- The guide only describes actions the service actually supports. In particular, it must
  not offer deleting a resource.
- The guide must stay in step with the service: whenever a feature, rule, or limit
  changes, the guide is updated at the same time.

## Rules and Limits

### File size
- **Each file may be at most 10 MB.** Larger uploads, and replacements larger than this,
  are rejected with a clear message.

### Lifetime and expiry
- Each resource is available for **24 hours** after it was uploaded or last replaced.
- Expired resources are removed automatically and can no longer be viewed or listed.
- Storage is temporary: if the service restarts, all resources are lost. Users must not
  rely on it as their only copy of anything.

### Open access (intentional)
- **No authentication is required for any action.** Anyone who can reach the service can
  upload, view, list, and replace resources.
- **Anyone can overwrite any resource.** This is a deliberate feature, not a gap. It lets
  several people or agents work together on the same shared link without managing
  accounts, keys, or ownership.
- Because of this, the service is meant for trusted networks and non-sensitive content.

## Quality and Test Coverage
- The project must be covered comprehensively by automated tests.
- Every feature in this document must be tested, including both its successful outcomes and
  its rejections (missing file, empty file name, unknown or expired resource).
- Every rule and limit must be tested, including:
  - files at, just under, and over the 10 MB limit, for both uploads and replacements;
  - expiry after 24 hours, and the lifetime restarting when a resource is replaced;
  - open access: anyone can upload, view, list, and overwrite any resource.
- The resource list must be tested in both forms: the visual page for people and the
  structured form for automated tools, including when the list is empty.
- The agent skill guide must be checked automatically against this document, so it cannot
  drift: it must state the current limits and lifetime, describe every supported action,
  and offer no unsupported ones.
- No feature is considered complete until its tests exist and pass.

## Intended Users
- **People** sharing a file with others on the same network through a short link.
- **Automated agents and scripts** that produce content (for example, generated reports or
  web pages) and need a quick place to publish it for a human to view. AI agents learn
  how to do this from the agent skill guide.
- **Operators** who run the service on their own machine and keep it available.

## Out of Scope
- User accounts, permissions, or ownership of resources.
- Permanent or backed-up storage.
- Deleting a resource before it expires.
- Editing content inside the service. Changes are made by uploading a replacement.
